## 📋 版本概述

企业微信统一认证中心的首个正式版本。解决「一个企业微信自建应用要给多个业务域名提供扫码登录」的问题：企业微信后台只配置 `auth.example.com` 一个回调域名，本服务统一接收 OAuth 回调，用一次性 `state` 反查来源系统，用一次性 `ticket` 把登录结果转发给各业务系统，业务系统后端签名调用 `/api/verify` 换取用户身份后建立自己的会话。

服务端以 Go 1.26 实现，外部依赖仅 `gopkg.in/yaml.v3`，编译产物为单二进制；配套 Docker 镜像发布（阿里云 + Docker Hub）、多平台 Release 产物与完整文档体系。

---

## ✨ 新增特性

- **多域名统一回调** — 企业微信后台只配认证中心一个域名，业务系统数量不再受可信域名额度约束，新增系统只需白名单加一行
- **PC 扫码 + 企微内 H5 双模式** — `wecom.mode` 支持 `qrcode`（wwlogin 扫码）与 `inside`（`snsapi_base` 网页授权）切换
- **一次性 state/ticket 凭证** — 128 位随机、取出即删、短时效（默认 300s/60s），防 CSRF 与重放
- **verify 签名校验** — HMAC-SHA256 + 时间戳偏差校验（≤60s），恒定时间比较，ticket 绑定 `app` 归属
- **防 Open Redirect** — `app` 白名单只存服务端配置，`redirect` 仅接受站内相对路径
- **mock 演练模式** — 不连接企业微信即可本地走通完整登录链路，含模拟扫码页
- **生产就绪中间件** — 按 IP 限流（可配置）、结构化请求日志、panic 恢复、健康检查、优雅退出
- **access_token 缓存** — 提前 5 分钟刷新、并发加锁；可选通讯录接口补全姓名

## 🔄 API 变更

首个正式版本，初始接口清单：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/login?app=&redirect=` | 业务系统发起登录，302 至企业微信授权页 |
| GET | `/callback?code=&state=` | 企业微信回调，签发一次性 ticket 并 302 回业务系统 |
| POST | `/api/verify` | 业务系统后端签名兑换 ticket 换取 `userid`/`name` |
| GET | `/healthz` | 健康检查 |

## 🔄 升级说明

首次部署参考 `README.md` 部署章节（Docker / Release 二进制两条路径）与 `docs/manual.md`：

1. 在企业微信管理后台完成自建应用创建、可信域名与授权回调域配置（清单见 `docs/wecom-setup.md`）
2. 从 `config.example.yaml` 复制 `config.yaml`，填入 corpid/secret 与业务系统白名单，`wecom.mock` 置为 `false`
3. Docker 部署直接使用 `registry.cn-shenzhen.aliyuncs.com/zyx3721/wecom-auth-center:latest`（Docker Hub 同步发布 `zyx3721/wecom-auth-center`）
4. 上线前以 mock 模式本地演练全流程，真实扫码联调通过后再接入业务系统
